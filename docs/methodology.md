# 공정한 비교와 결과 해석

## 1. 바꾸는 것은 하나만

A와 B의 차이는 **비교 대상(플러그인·스킬·MCP) 하나**여야 합니다. 나머지는 모두 같게 둡니다.

| 같게 둘 것 | 이 도구가 하는 일 | 사용자가 할 일 |
|---|---|---|
| 모델 | `experiment.json`의 `model`을 양쪽에 `--model`로 고정 | 실험 중에 `/model`로 바꾸지 않기 |
| 출발점 | 실행 전마다 작업 폴더를 `fixture\`로 초기화 | 실습 원본을 측정 도중 바꾸지 않기 |
| 지시문 | 같은 파일을 양쪽에 그대로 전달 | 대화형에서는 같은 문장을 붙여 넣기 |
| 권한 | 헤드리스는 같은 `--permission-mode` | 대화형에서는 확인 창에 같은 답 |
| MCP | A는 비어 있음, B는 `mcp-B.json`만 | 비교 대상이 아닌 서버를 B에 넣지 않기 |
| Claude Code 버전 | `conditions.json`에 기록 | 측정 도중 업데이트하지 않기 |

## 2. 반복 횟수

같은 지시문도 실행마다 결과가 달라집니다.

- **최소 3회, 영상에 숫자를 넣는다면 5회 이상**을 권장합니다.
- 평균과 함께 성공/전체 횟수를 같이 보여 주세요. "B가 평균 20% 빠르다"보다
  "5번 중 A는 3번, B는 5번 성공"이 더 정직한 비교일 때가 많습니다.
- 차이가 작으면(대략 10% 안쪽) 반복 횟수를 늘리기 전에는 "차이가 있다"고 말하지 않는 편이 안전합니다.

## 3. 순서와 캐시

- 프롬프트 캐시 때문에 먼저 실행한 쪽보다 나중에 실행한 쪽이 비용이 덜 나올 수 있습니다.
  `run-headless.ps1`은 회차마다 A/B 순서를 바꿔 이 효과를 상쇄합니다.
- 대화형 비교에서는 거의 동시에 시작하세요.

## 4. 측정값 읽는 법

| 값 | 의미 | 주의 |
|---|---|---|
| `CostUSD` | Claude Code가 보고한 API 기준 비용 | 구독 요금제에서는 실제 청구액이 아닌 추정값. 상대 비교용 |
| `Turns` | 에이전트 순환 횟수 | 적을수록 좋다고 단정할 수 없음(검증을 더 했을 수도 있음) |
| `Seconds` | 전체 실행 시간 | 네트워크·서버 상태 영향이 큼 |
| `OutputTokens` | 모델이 생성한 토큰 | 스킬이 장황한 출력을 유도하는지 보기 좋음 |
| `CacheReadTokens` | 캐시에서 읽은 입력 토큰 | 스킬·플러그인이 컨텍스트를 얼마나 키우는지 간접 지표 |
| `ChangedFiles` | 원본 대비 바뀐 파일 수 | 품질 지표가 아님. 범위를 벗어난 변경을 찾는 단서 |
| `IsError` / `Subtype` | 실행 실패 여부 | 예산 초과(`--max-budget-usd`)도 여기 나타남 |

## 5. 품질 판정

숫자보다 중요한 것은 "결과가 맞았는가"입니다. 지시문을 쓸 때 판정 기준을 미리 정해 두세요.

- **자동 판정 가능한 과제를 고르기**: 테스트 통과, 빌드 성공, 특정 출력 일치.
  `results\...\A-1-work\`에서 직접 테스트를 돌려 판정할 수 있습니다.
- **채점표 쓰기**: 사람이 판정해야 하면 항목을 미리 정합니다(예: 요구사항 충족 / 불필요한 변경 없음 / 설명 정확).
- **블라인드 판정**: 가능하면 `A-1-work`, `B-1-work` 이름을 가리고 판정합니다.
- 판정 결과는 `NOTES.md`의 "관찰"에 실행별로 적습니다.

## 6. 영상·자료로 만들 때

- **첫 장면에 환경 증명**: 양쪽 `/context`(또는 `/plugin`)를 보여 주고 "왼쪽은 기본, 오른쪽은 OO만 추가"라고 말합니다.
- **기준 정의를 한 줄로**: "기본 = Claude Code + claude.ai 기본 스킬, 계정 플러그인·MCP 제외" 같은 정의를 자막이나 설명란에 넣습니다.
- **숫자는 반복 측정 결과로**: 화면 비교는 장면 연출용으로, 비교표는 `REPORT.md` 값으로 씁니다. 회차 수를 함께 밝힙니다.
- **조건 공개**: 모델, Claude Code 버전, 권한 모드, 측정 날짜를 설명란에 적습니다(`conditions.json`에 모두 있음).
- **비교 대상 출처**: 플러그인·스킬의 저장소 주소와 버전(커밋)을 설명란에 적습니다.
- **편향 주의**: 비교 대상에 유리한 과제만 고르지 말고, 불리할 수 있는 과제도 하나 넣으면 신뢰도가 올라갑니다.
